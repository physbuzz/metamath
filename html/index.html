Intro

This project started from reading through Norm Megill's public domain Metamath book, but grew into its own study project. My goals are:

  1. Build up to making formally verified metamathematical statements, inside Metamath. At the outset, it's very difficult to determine how ambitious to be. The best path to this appears to be doing this through set.mm, from which we use set theory tools to make metamathematical statements.
  2. Learn logic and metamathematics from a verifier-first perspective. "If it's not formally verified, it's folk knowledge, it's scattering bones and reading them"--is what I'd like to say, but in fact we still have to touch base with references. I haven't found any book that goes as far as I would like, perhaps they exist in the Lean- or Agda-sphere.
  3. Learn the history and terminology around important areas, while connecting to and citing literature. Thus, if I say a nonsequitur in conversation with logicians, I can at least say "oh, I was using the definition in Gaifman's 2002 student notes, what one are you using?" This helps us avoid (but doesn't entirely prevent) developing totally wacko ideas while completing independent studies.
  4. Deign to learn some of the important English language proofs, where we only our brains as proof checkers. This is how most of the literature works so it really can't be avoided. Also, sometimes, such as in peano.mm, the metamath database contains a lot of exposition in the form of prose assertions justifying the properties of the axioms.
  5. Perhaps learn some type theory (formalized in .mm) while we're at it.

The reason for my staunch "if it's not formally verified it doesn't exist" stance is not philosophy-first nor because I think it's pedagogically good. I simply don't understand the books. I can get an A in the coursework and repeat the English language proofs, but I am not sure that I'm not getting them wrong. I know that the verifier consisting of the examiner's brain finds the argument convincing, but I can't be sure that there's any sense to it at all. So I've been deeply deeply confused for a number of years and only now am I repairing that.

AI usage: I've found AI to be an absolutely horrible teacher, an OK problem set generator, and an absolutely amazing reference-finder, so I use it 0% for teaching and terminology, 60% problem set generations + human review (in the form of actually doing the problems), and 95% for finding references. For teaching, I think it gets stuck in a deep "intro to proofs" attractor. Dawg I'm a decade out from intro to proofs. Doesn't help that there's much less material with a verifier-first perspective. Primary Sources I'm using

  • The metamath book. You know it, I know it.
  • Harper, Practical Foundations for Programming Languages. I'm using ch1-3. when I saw "alpha equivalence" in peano.mm I knew I had to.
  • Kleene 1952, Introduction to Metamathematics.
  • Mendelson, Introduction to Mathematical Logic.
  • Sam Buss Introduction to Mathematical Logic (course notes, 2023).

Papers:

  • How to Believe a Machine-Checked Proof. Essential reading.
  • The Challenge of Computer Mathematics. Essential reading. Barendregt coined the term "de Bruijn criterion" in 1997.
  • The Impact of the Lambda Calculus in Logic and Computer Science by Henk Barendregt, Bulletin of Symbolic Logic 3(2), 181–215 (1997) (paper that coined the term, 'cuz I might as well link it).
  • Gaifman, A Hilbert Type Deductive System for Sentential Logic, Completeness and Compactness (2002). This is at the very least the most direct definition of a Hilbert-style formal system. It seems to be a bit overly-broad though, I'd argue it says Metamath itself is Hilbert-style though we say colloquially that the logics represented in various Metamath databases need not be Hilbert-style. But Norm Megill et al are very careful to never say "Metamath is Hilber-style." So whatever, we call Metamath Hilbert-inspired and move on, I was a stickler over terminology for way too long.
