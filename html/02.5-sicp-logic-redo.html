2.5 Bonus Chapter: Metamath as Logic Programming (cf. SICP 4.4)

Note

This is a bonus chapter, written as a "lost section" of Structure and Interpretation of Computer Programs (SICP) 4.4. It assumes the query system of SICP 4.4.4 is already built and understood. If you have not read that section, skip this chapter; nothing later depends on it.

Warning

This chapter was AI-generated and has not been human-reviewed. All program output and all numbers in the tables come from running the files in code-02/.

SICP 4.4 remarks in passing that logic programming grew out of automatic theorem proving. This chapter takes the remark literally. The database of Megill ch. 2 (demo0.mm) is translated into rules for the SICP query system, and the system is then asked to check a Metamath proof, to say what a proof proves, to enumerate theorems, and to find the proof of |- t = t and print it as a Metamath proof.

The query system itself is not modified. code-02/query.rkt is SICP 4.4.4 as printed, with run-query in place of the read-eval-print loop. Everything in this chapter is done by choosing what the rules say.

Terminology. In this chapter frame always means the SICP frame: a table of pattern-variable bindings. It does not mean Megill's frame (an assertion together with its mandatory hypotheses).

2.5.1 The dictionary

Metamath Query system
expression, a string of math symbols list structure: the parse tree of the string
$c constant symbol
$v variable occurring in an axiom pattern variable ?t
$v variable occurring in the theorem being proved symbol
$a statement rule: the conclusion is the assertion, the body is the and of its mandatory hypotheses
$f, $e hypothesis of the theorem being proved assertion
$p statement a query; once proved, one more rule
substitution frame
Megill's frame a rule: conclusion and body
proof not present yet; see 2.5.3

Four of these rows need a comment.

Expressions become trees. Metamath substitutes strings for variables. The SICP unifier binds a variable to one list element, so ( t + 0 ) = t must be given its structure up front: ((t + 0) = t). Metamath's parentheses become Lisp's, and weq gets the parentheses it never had. Nothing is lost as long as the grammar is unambiguous, which Metamath itself does not check but every sane database satisfies. One spelling changes: | is special to the Scheme reader, so the typecode |- is written ⊢.

Variables split in two. In a2 $a |- ( t + 0 ) = t $. the variable t stands for any term, so it becomes the pattern variable ?t. In the theorem th1 $p |- t = t $. the proof must work for an arbitrary but fixed t, so there t is a plain symbol, and the floating hypothesis tt $f term t $. is the assertion (term t). If the query were (⊢ (?t = ?t)), the system would be free to answer (⊢ (0 = 0)), which is an instance and not the theorem.

A rule without a body is an axiom scheme. SICP introduces bodiless rules with (rule (same ?x ?x)) and does not dwell on them. A database "assertion" that matches infinitely many queries is a strange piece of data, but it is exactly what a logician calls an axiom scheme: (rule (⊢ ((?t + 0) = ?t))) asserts every instance at once.

Megill's frame is a rule; Megill's substitution is a frame. The two books use the same word for different things, and the correspondence crosses over.

2.5.2 The rules

Each $a statement of demo0.mm is translated mechanically. For example

metamath
min $e |- P $.   maj $e |- ( P -> Q ) $.   mp $a |- Q $.

has mandatory hypotheses wp, wq, min, maj and becomes

racket
(rule (⊢ ?Q) (and (wff ?P) (wff ?Q) (⊢ ?P) (⊢ (?P -> ?Q))))

The whole database is seven rules and one assertion.

demo0-rules.rkt
#lang sicp
;; This file was entirely AI generated by fable 5.2.
;; demo0.mm (Megill ch. 2) as rules for the unmodified query system.
(#%require "query.rkt" "mm.rkt")

;; Each $a statement is one rule: the conclusion is the assertion, the body
;; is the conjunction of its mandatory hypotheses in Metamath's order.
;; The system tries the most recently added rule first.
(add! '(rule (wff (?P -> ?Q))                               ; wim
             (and (wff ?P) (wff ?Q))))
(add! '(rule (wff (?t = ?r))                                ; weq
             (and (term ?t) (term ?r))))
(add! '(rule (term (?t + ?r))                               ; tpl
             (and (term ?t) (term ?r))))
(add! '(rule (term 0)))                                     ; tze
(add! '(rule (⊢ ?Q)                                         ; mp
             (and (wff ?P) (wff ?Q) (⊢ ?P) (⊢ (?P -> ?Q)))))
(add! '(rule (⊢ ((?t = ?r) -> ((?t = ?s) -> (?r = ?s))))    ; a1
             (and (term ?t) (term ?r) (term ?s))))
(add! '(rule (⊢ ((?t + 0) = ?t))                            ; a2
             (term ?t)))

;; The floating hypothesis of th1, `tt $f term t $.`, is an assertion.
(add! '(term t))

;; Syntax questions terminate: every rule application strips a connective.
(show 5 '(wff ((t + 0) = t)))
(show 5 '(wff ((t + 0) = (t -> t))))
(show 5 '(term (?x + 0)))
(show 5 '(wff ?x))

;; Axiom instances: only the first answer is safe to ask for, because mp
;; applies to every goal and is tried after the axioms.
(show 1 '(⊢ ((t + 0) = t)))
(show 1 '(⊢ ((0 = t) -> ((0 = ?x) -> (t = 0)))))

What this shows:

  • Asking whether something is a term or a wff works, and terminates, because each rule application removes one connective from the goal. This is parsing.
  • A query with a variable runs the grammar backwards and generates expressions. The stream is infinite; show takes a prefix.
  • Order matters, as SICP 4.4.3 warns. The system tries the most recently added rule first, and it evaluates the first rule's body eagerly. wim is added before weq so that (wff ?x) starts with a rule that can finish. With the two swapped, (wff ?x) recurses forever before producing anything.
  • An axiom instance is found, but only the first answer is safe to ask for. mp applies to every goal, so the stream of all answers never ends.
  • (⊢ (t = t)) does not return. No axiom matches, so mp is applied. Its body starts with (wff ?P), whose first answer is ?P = (t = t), and the body then asks for (⊢ (t = t)) again.

Reordering the conjuncts does not repair the last point. With (⊢ (?P -> ?Q)) first the search is goal-directed, and the query still does not return: a1's body (term ?t) picks ?t = t before the minor premise is examined, and the system is again proving (t = t) in order to prove (t = t). The depth-first search needs a bound.

2.5.3 Proofs and depth are two more arguments

The standard logic-programming move is to add arguments to the relation rather than features to the evaluator. Every statement gets two more:

racket
(typecode expression proof budget)
  • proof: a tree. The proof of a rule's conclusion is the rule's label applied to the proofs of its mandatory hypotheses, in Metamath's order: (mp ?wp ?wq ?min ?maj). A hypothesis of the theorem is proved by its own label: tt.
  • budget: a unary numeral. A conclusion with budget (s ?n) gives each hypothesis budget ?n. A query with budget (s (s (s z))) can therefore only produce proof trees of height at most 3, and the search is finite.

Iterative deepening, trying budget 1, 2, 3, … until an answer appears, is a five-line loop around run-query (deepen in code-02/mm.rkt). It is not part of the evaluator.

#lang sicp
;; This file was entirely AI generated by fable 5.2.
;; Small helpers around the unmodified query system in query.rkt.
(#%require "query.rkt")
(#%provide (all-defined))

(define (stream-head s n)               ; first n elements, as a list
  (if (or (= n 0) (stream-null? s))
      '()
      (cons (stream-car s)
            (if (= n 1) '() (stream-head (stream-cdr s) (- n 1))))))

(define (add! x)                         ; add a rule or an assertion
  (run-query (list 'assert! x))
  (if false false))

(define (show n query)                  ; print the first n answers
  (display ";;; ") (display-tree query 4) (newline)
  (let ((answers (stream-head (run-query query) n)))
    (if (null? answers) (begin (display "(no answers)") (newline)))
    (for-each show-tree answers))
  (newline))

;; Number of rule applications attempted so far (SICP's own counter).
(define (applications) rule-counter)

;; Depth budgets are unary numerals: 3 = (s (s (s z))).
(define (peano n) (if (= n 0) 'z (list 's (peano (- n 1)))))

;; Iterative deepening: run (make-query budget) for budget = 1, 2, ... max
;; and return (depth first-answer), or false.
(define (deepen make-query max)
  (define (try d)
    (if (> d max)
        false
        (let ((answers (run-query (make-query (peano d)))))
          (if (stream-null? answers)
              (try (+ d 1))
              (list d (stream-car answers))))))
  (try 1))

;; Print a proof tree, one subproof per line once it gets long.
(define (width tree)
  (if (pair? tree)
      (+ 1 (length tree) (apply + (map width tree)))
      (string-length (if (symbol? tree) (symbol->string tree) "0"))))
(define (display-tree tree indent)
  (define (spaces n) (if (> n 0) (begin (display " ") (spaces (- n 1)))))
  (if (or (not (pair? tree)) (< (width tree) 50))
      (display tree)
      (let ((indent (+ indent 2 (width (car tree)))))
        (display "(") (display (car tree)) (display " ")
        (display-tree (cadr tree) indent)
        (for-each (lambda (sub)
                    (newline) (spaces indent) (display-tree sub indent))
                  (cddr tree))
        (display ")"))))
(define (show-tree tree) (display-tree tree 0) (newline))

;; A proof tree (label subproof ...) in postorder is a Metamath proof.
(define (flatten-proof p)
  (if (pair? p)
      (append (apply append (map flatten-proof (cdr p))) (list (car p)))
      (list p)))

;; Replace every pending syntax goal (typecode expr) in a proof tree by a
;; proof of it, found with one conjunctive query (typecode expr ?proof).
(define (elaborate proof typecodes)
  (define goals '())
  (define (pending? p) (and (pair? p) (memq (car p) typecodes)))
  (define (collect p)
    (cond ((pending? p)
           (set! goals (cons (list (car p) (cadr p) '?proof) goals)))
          ((pair? p) (for-each collect (cdr p)))))
  (define (rebuild p)
    (cond ((pending? p)
           (let ((found (caddr (car goals))))
             (set! goals (cdr goals))
             found))
          ((pair? p) (cons (car p) (map rebuild (cdr p))))
          (else p)))
  (collect proof)
  (set! goals (number-goals (reverse goals) 1))
  (if (not (null? goals))
      (set! goals (cdr (stream-car (run-query (cons 'and goals))))))
  (rebuild proof))

(define (number-goals goals i)          ; ?proof -> ?proof1, ?proof2, ...
  (if (null? goals)
      '()
      (cons (list (car (car goals)) (cadr (car goals))
                  (string->symbol
                   (string-append "?proof" (number->string i))))
            (number-goals (cdr goals) (+ i 1)))))

One relation, four uses

statement proof budget what the query does
open given open computes what a proof proves
given given open checks a proof
open open given enumerates theorems with their proofs
given open 1, 2, 3, … searches for a proof

This is the same phenomenon as SICP's append-to-form running backwards. The enumeration also previews 2.5.5: there are 10 answers within budget 2, 222 within budget 3, and 54,910 within budget 4.

The proof tree is a Metamath proof. A Metamath proof is the postorder traversal of this tree, because the verifier is a stack machine: a label pops its hypotheses and pushes its conclusion. flatten-proof is that traversal. The first line of output is Megill's proof of th1, token for token.

Checking. With the proof given, the query does what a Metamath verifier does, written as recursion on the tree instead of a loop over a stack. The label at the root selects one rule. The subproofs in the floating slots are run "backwards", from proof to expression, and so compute the substitution: (wff ?P (weq (tpl tt tze) tt) ?n) binds ?P to ((t + 0) = t). This is the job of $f hypotheses in Metamath. The essential hypotheses are then comparisons. A real verifier needs no unification at all, since it substitutes and tests equality. The query gets the same effect from a unifier in which one side is always fully known. No budget is needed: the proof tree shrinks at every step. The answer's budget (s (s (s (s (s (s ?n)))))) reports that the tree has height 6.

Searching. Here two-way unification earns its keep. The goal (⊢ (?P -> (t = t))) is unified with the conclusion of a1 or mp, and variables on both sides get bound. The occurs check (depends-on? in SICP) matters: without it ?P could be bound to (?P -> ?Q), a "wff" that no finite string spells.

The search finds a proof at budget 6 after 528 rule applications, and the proof is identical to Megill's.

Order of hypotheses. The mp rule in this file lists its hypotheses as major premise, minor premise, then the two wffs. The proof term keeps Metamath's order regardless. The body order decides whether the search is feasible:

body of mp search for (⊢ (t = t))
maj, min, wP, wQ 528 rule applications, a fraction of a second
wP, wQ, min, maj (Metamath's order) not finished after 15 minutes

Metamath's order starts with (wff ?P ?wp ?n) while ?P is unknown. That enumerates every wff within the budget and tests each one: generate and test. With the essential hypotheses first, unification with the goal determines ?P, and the wff conjuncts merely parse it.

Work variables. The Metamath proof assistant does the same thing. assign 1 mp creates the steps |- $2 and |- ( $2 -> t = t ) with a work variable $2, later steps determine $2 by unification, and improve all fills in the syntax proofs at the end (see question 18 of chapter 1). An unbound pattern variable is a work variable.

One weakness remains. The bodies of a1 and a2 consist only of floating hypotheses, so they run as soon as the axiom is applied, possibly before a later step has determined ?t. That is still generate and test, on a small scale. The next section removes it.

2.5.4 Propositional calculus: a database that grows

The database of chapter 4 has two syntax rules, three axioms, ax-mp, and 36 theorems that are proved in order, each one available to those after it. code-02/prop.rkt states all 40 statements as data and translates them with one procedure, statement->rule. Three things differ from the hand-written rules above.

Syntax goals are postponed. A rule's body holds only the essential hypotheses. The floating slots of the proof term hold the pending goals themselves:

racket
(rule (⊢ ?ps (ax-mp (wff ?ph) (wff ?ps) ?h1 ?h2) (s ?n) ?thm)
      (and (⊢ (?ph -> ?ps) ?h2 ?n ?thm)
           (⊢ ?ph ?h1 ?n ?thm)))

After the search, elaborate (in mm.rkt) collects the pending (wff …) goals of the proof it found and discharges them with a single query against the syntax rules. A work variable that the proof never constrained is bound by that query to the first wff it finds; any wff would do. On demo0 this scheme finds the same proof of t = t in 25 rule applications instead of 528.

Hypotheses are assertions, tagged by theorem. To prove syl, its variables become the symbols ph, ps, ch and its hypotheses are asserted as data:

racket
(hyp syl (ph -> ps) syl.1)
(hyp syl (ps -> ch) syl.2)

One rule, (rule (⊢ ?stmt ?label (s ?n) ?thm) (hyp ?thm ?stmt ?label)), makes them usable. The extra argument ?thm names the theorem being proved and is passed unchanged to every subgoal. The query system cannot retract assertions, and without the tag the hypotheses of syl would leak into every later proof.

A proved theorem becomes a rule. After each search the theorem is added with statement->rule, exactly like an axiom. Subgoals are tried largest first, which generalizes "major premise before minor".

(define (label s) (car s))
(define (hypotheses s) (cadr s))
(define (conclusion-of s) (caddr s))

;; ---- list utilities -------------------------------------------------
(define (filter keep? l)
  (cond ((null? l) '())
        ((keep? (car l)) (cons (car l) (filter keep? (cdr l))))
        (else (filter keep? (cdr l)))))
(define (occurs? x tree)
  (if (pair? tree)
      (or (occurs? x (car tree)) (occurs? x (cdr tree)))
      (eq? x tree)))
(define (size tree)
  (if (pair? tree) (+ (size (car tree)) (size (cdr tree))) 1))
(define (insert-by-size x sorted)       ; larger expressions first
  (cond ((null? sorted) (list x))
        ((> (size (car x)) (size (car (car sorted)))) (cons x sorted))
        (else (cons (car sorted) (insert-by-size x (cdr sorted))))))
(define (sort-by-size l)
  (if (null? l) '() (insert-by-size (car l) (sort-by-size (cdr l)))))
(define (numbered-symbols prefix n)
  (define (loop i)
    (if (> i n)
        '()
        (cons (string->symbol (string-append prefix (number->string i)))
              (loop (+ i 1)))))
  (loop 1))

;; ---- the translation ------------------------------------------------
(define variables '(?ph ?ps ?ch ?th ?ta))   ; in $f order
(define constants '(ph ps ch th ta))
(define float-labels '(wph wps wch wth wta))

;; (ax-mp (?ph (?ph -> ?ps)) ?ps) becomes
;; (rule (⊢ ?ps (ax-mp (wff ?ph) (wff ?ps) ?h1 ?h2) (s ?n) ?thm)
;;       (and (⊢ (?ph -> ?ps) ?h2 ?n ?thm) (⊢ ?ph ?h1 ?n ?thm)))
;; The proof term lists the mandatory hypotheses in Metamath order; the
;; body tries the essential hypotheses largest first.
(define (statement->rule s)
  (let ((floats (filter (lambda (v) (occurs? v (cdr s))) variables))
        (slots (numbered-symbols "?h" (length (hypotheses s)))))
    (let ((subgoals
           (map (lambda (pair) (list '⊢ (car pair) (cdr pair) '?n '?thm))
                (sort-by-size (map cons (hypotheses s) slots)))))
      (list 'rule
            (list '⊢
                  (conclusion-of s)
                  (cons (label s)
                        (append (map (lambda (v) (list 'wff v)) floats)
                                slots))
                  '(s ?n)
                  '?thm)
            (cons 'and subgoals)))))

;; To prove a statement, its variables become constants and its
;; hypotheses become assertions (hyp <theorem> <expression> <label>).
(define (constant-for v)
  (define (loop vs cs)
    (cond ((null? vs) v)
          ((eq? v (car vs)) (car cs))
          (else (loop (cdr vs) (cdr cs)))))
  (loop variables constants))
(define (freeze tree)
  (if (pair? tree)
      (cons (freeze (car tree)) (freeze (cdr tree)))
      (constant-for tree)))
(define (hypothesis-labels s)
  (numbered-symbols (string-append (symbol->string (label s)) ".")
                    (length (hypotheses s))))
(define (assert-hypotheses! s)
  (for-each (lambda (h l) (add! (list 'hyp (label s) (freeze h) l)))
            (hypotheses s)
            (hypothesis-labels s)))

(define (setup!)
  (for-each (lambda (c l) (add! (list 'wff c l))) constants float-labels)
  (add! '(rule (wff (-. ?ph) (wn ?p)) (wff ?ph ?p)))
  (add! '(rule (wff (?ph -> ?ps) (wi ?p ?q)) (and (wff ?ph ?p) (wff ?ps ?q))))
  (for-each (lambda (s) (add! (statement->rule s))) axioms)
  (add! '(rule (⊢ ?stmt ?label (s ?n) ?thm) (hyp ?thm ?stmt ?label))))

;; Search for a proof of statement s; returns (depth proof-tree) or false.
(define (prove s max-depth)
  (assert-hypotheses! s)
  (let ((found (deepen (lambda (budget)
                         (list '⊢ (freeze (conclusion-of s)) '?proof
                               budget (label s)))
                       max-depth)))
    (and found (list (car found) (caddr (cadr found))))))

2.5.5 How hard is proof search?

Fix a database in which $b$𝑏 rules can apply to a typical goal and the main rule has two essential hypotheses, as ax-mp does. There are two ways to measure a proof, and they give the two answers one might guess.

By size. A proof with $n$𝑛 applications of ax-mp is a binary tree with $n$𝑛 internal nodes and $n+1$𝑛+1 leaves. There are $C_n \approx 4^n$𝐶𝑛≈4𝑛 such trees (the Catalan numbers) and $A$𝐴 choices of axiom per leaf, so the number of proof skeletons is

$$C_n \, A^{n+1} \approx (4A)^n .$$𝐶𝑛𝐴𝑛+1≈(4𝐴)𝑛.

Search is exponential in the size of the proof, with the number of axioms in the base.

By depth. A tree of height $d$𝑑 can have $2^{d-1}$2𝑑−1 leaves. Let $T(d)$𝑇(𝑑) be the number of skeletons of height at most $d$𝑑. Then

$$T(d) = A + T(d-1)^2, \qquad T(d) \approx A^{2^{d-1}} .$$𝑇(𝑑)=𝐴+𝑇(𝑑−1)2,𝑇(𝑑)≈𝐴2𝑑−1.

Search is doubly exponential in the depth of the proof. A depth-bounded search, which is what the query system does, pays this price.

Both are worst cases. Unification rejects most skeletons, and many skeletons prove the same theorem.

Why lemmas win

Adding a theorem as a rule raises the branching factor $b$𝑏 by one and lowers the size $n$𝑛 of every proof that can use it. Cost is roughly $b^n$𝑏𝑛, and $n$𝑛 is in the exponent. peirce is 21 steps from the axioms. From the lemmas of chapter 4 it is three rule applications, (pm2.61i (syl pm2.21 pm2.27) (con4d pm2.21)).

The price is that $b$𝑏 keeps growing. With about 40 rules, exhausting budget 3 already costs 8 million rule applications. set.mm has tens of thousands of theorems, and chapter 4 notes that Metamath's own improve last /depth n gets expensive at depth 2 or 3, for this reason. A human proof author is, in these terms, an oracle that picks the right lemma at each step, and choosing which statements deserve to be lemmas is most of the mathematical work.

2.5.6 Disjoint variables

Everything above ignores $d. This note describes what $d would change; it is not implemented in code-02/.

A restriction $d x y $. on an axiom is a condition on the substitution: the expressions substituted for x and y must have no variable in common, and every pair of variables drawn from the two must itself be declared disjoint in the theorem being proved. In the query system that is one more conjunct at the end of the rule body, a filter in the sense of SICP's lisp-value:

racket
(rule (⊢ (?ph -> (A. ?x ?ph)) (ax-5 ?wph ?vx))
      (and (wff ?ph ?wph) (setvar ?x ?vx)
           (lisp-value disjoint? ?x ?ph)))

where disjoint? is a Scheme procedure that walks the two expressions and looks up each pair of symbols in the theorem's $d list.

  • Checking is unaffected. The substitution is fully known when the filter runs.
  • Search is not made larger. $d only rejects proofs, so every proof found with $d is also found without it.
  • Search is made more awkward, in the same way that not and lisp-value are awkward in SICP 4.4.3: a filter needs its variables bound. During search the filter can be reached while ?ph still contains work variables. It then has to be postponed, as the syntax goals are in 2.5.4, which means the search can spend time in a branch that the filter later kills.
  • Leftover work variables can no longer be filled arbitrarily. In 2.5.4 an unconstrained work variable was bound to the first wff available. Under $d the choice must satisfy the pending restrictions, and the usual answer is a fresh dummy variable declared disjoint from everything else. Proofs in set.mm that mention variables absent from the theorem statement are doing exactly this.

So $d does not wreck proof search. It adds a class of constraints that a plain left-to-right evaluator handles badly and a constraint-postponing one handles naturally.

2.5.7 Definitions and algorithms worth knowing

  • Unification, most general unifier. The substitution computed by unify-match. Any other substitution that makes the two patterns equal is an instance of it. This is why a search can return a proof with work variables still unbound: it has found the most general proof of that shape.
  • Matching is unification with variables on one side only (pattern-match). Verifying a Metamath proof needs less than matching; proof search needs unification.
  • Occurs check. Refusing to bind ?x to an expression containing ?x. SICP includes it. Prolog omits it by default for speed, which is unsound when the rules are meant as logic.
  • Backward chaining starts from the goal and applies rules conclusion-first; the query system does this. Forward chaining starts from the axioms and derives everything derivable; count.py does this. Backward search is goal-directed but repeats work. Forward search shares work but is undirected.
  • Iterative deepening. Depth-first search with budget 1, 2, 3, …. It finds a shallowest proof and uses little memory. Re-searching the shallow levels costs little because the last level dominates.
  • Condensed detachment. ax-mp combined with unification: from the most general forms of the major and minor premise, produce the most general conclusion. A proof skeleton written in Polish notation, such as DD211 for id, is a D-proof. The proof terms of 2.5.4 with the syntax slots removed are D-proofs.
  • Proof term. The tree recording which rule was used where. Under the Curry–Howard correspondence ax-1 and ax-2 are the types of the combinators K and S, ax-mp is function application, and the proof DD211 of ph -> ph is the program S K K. Proof search is then program synthesis from a type.
  • Work variable (metavariable). An unknown to be determined later by unification: $2 in the Metamath proof assistant, an unbound ?P here.
  • Generate and test versus constrain, then generate. The lesson of the two orderings in 2.5.3. Goals that only enumerate should run last, when unification has already fixed their arguments.
  • Tabling. Recording which goals have been tried, to cut loops and avoid repeated work. SICP exercise 4.67 asks for a loop detector of this kind. It is the backward-chaining counterpart of storing distinct theorems.
  • Decision procedures. Propositional calculus is decidable by truth tables, and the completeness proof can be made to output a Hilbert-style proof. For this fragment, search is the wrong tool once a statement is more than a few steps away; it is the right subject for studying search precisely because the ground truth is cheap.
